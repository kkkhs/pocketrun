## 最终目标与当前阶段

PocketRun 的最终目标是**复刻 Ditto 整体背后的功能，同时通过教程理解它们的框架和运行逻辑**。章节按能力递进，不把固定 Demo、最小 Linux 环境或两步任务当作最终功能范围。

当前第 1—11 章建立了两条执行通道及其上的受控模型循环：

- Android：App 自有 ADB → UID 2000 的 `app_process` → typed Binder → 后端持有的虚拟屏、截图、UI 树与定向输入。
- 文件与 Linux：普通 App UID 的私有工作数据 → ProcessBuilder/PRoot → 非交互命令或 JNI/PTY。
- 工具与模型：原 TaskHost 的校验、手机批准、取消与清理 → 单任务账本 → Kotlin 模型循环。

**这些是阶段能力，不是完整功能复刻完成的声明。** 扩充功能时保持这条执行架构；功能数量、协议和行为覆盖需要逐项对照。

## 对照依据

现有 Ditto 对照主要来自此前检查的 **0.1.14 APK 与部分可读重建方法**，不是完整原始 App 源码，也不是当前所有版本的行为清单。已有记录见[第 7 章程序来源与 Ditto 对照](chapter-7.md)。

已记录的静态事实：

- APK 使用 `nativeLibraryDir` 下的 PRoot/loader，并有 Termux 风格 JNI/PTY 路径。
- APK 携带 Alpine 3.24.3、515 个归档条目及 `apk` 程序。
- JADX 1.5.1 的重建有 32 个错误，不能补猜缺失方法。
- [ditto-termux-packages](https://github.com/WindySha/ditto-termux-packages) 是源码候选，尚未核实为整个 App 源码或该 APK 的对应版本。

这些事实可以支持运行机制和分发范围比较。**含有 `apk` 不等于已经验证包安装、仓库网络和重启持久性；静态方法也不等于证明所有设备上的运行效果。** 没有直接证据的功能标为待核实，不凭名称或同类产品推断。

## 当前缺口清单

| 项目 | PocketRun 当前能力 | 待完成或核实 |
| --- | --- | --- |
| Linux 用户态分发 | Alpine 3.22.8 派生的最小 BusyBox/musl，四个 ELF、两个代码绑定 | 明确小于已记录的 Ditto rootfs 范围；补齐功能所需程序、库和目录。版本号不同本身不等于功能缺失 |
| 包管理 | 当前没有 `apk`、包仓库与安装入口 | 缺少包安装能力；先核实 Ditto 的真实安装/更新/网络/持久化流程，再实现并处理 Android 执行约束和分发许可 |
| Agent 工具面 | 设备信息、固定 CSV、受限虚拟屏三个工具 | 固定 CSV 不是通用文件/命令工具；获取 Ditto 完整工具及参数/结果协议后逐项扩充。用户手动 PTY 可以解释 shell 输入，不等于模型已有通用终端工具 |
| Android 操作目标 | 固定 Demo 的截图、UI 树、点击和可打印 ASCII 输入 | 尚未形成一般 App 的任务操作面；需核对目标 App 启动、节点选择、导航、滚动、文字输入等实际支持范围与授权规则 |
| 终端呈现 | 真实 PTY、输入、尺寸和控制字符；React 有界文字预览 | 不具备完整终端模拟器的 ANSI/光标/全屏程序呈现；是否及怎样对齐 Ditto 的终端前端仍需直接核实 |
| 完整跨能力任务 | 已分别验证显示操作、文件命令、工具批准和设备+CSV两步模型任务 | “读取/整理文件 → 操作目标 App → 保存结果”的完整任务尚未串联验收；能力分段通过不能替代完整流程 |
| 模型输入与结果协议 | Kotlin 官方 SDK、完整消息回放、有限安全工具摘要 | 尚无给模型发送截图/UI内容的观察通道；需核对 Ditto 的模型观察、工具结果、配置及错误恢复协议，再按隐私/授权边界实现 |
| 跨任务状态与恢复 | 当前有界任务、请求取消、资源死亡/恢复检查 | 任务账本不跨 App 进程死亡持久化；完整动作恢复/避免重复提交、跨任务记忆尚未实现，Ditto 对应行为仍待核实 |
| 设备与降级覆盖 | 已有专用设备上若干固定能力和故障验证 | 未覆盖全部 Android/OEM/目标 App；Ditto 的兼容分支及降级行为尚未完整对照，不因本机通过宣称全设备一致 |

表中的后半部分记录的是 **PocketRun 已知阶段边界和后续对照任务**，并非宣称每一项都已证实存在于 Ditto。只有确认原产品有对应能力，才进入逐项功能复刻验收；额外产品能力单独标明来源。

## 尚待建立的原产品清单

完整功能对照还需要补齐以下证据：

1. 原产品工具目录：名字、参数、结果、授权及错误语义。
2. Android 操作范围：启动、目标选择、输入、观察及支持的 App/显示类型。
3. Linux 与终端工作流：程序安装、命令会话、数据保存及恢复。
4. 模型宿主：真实语言/进程、模型接口、观察内容和工具回合流程。
5. 任务生命周期：取消、超时、死亡、持久化、重试及动作恢复。

MCP、产品 subagent、多任务、长期记忆、回放和大规模 eval 目前没有本地 Ditto 直接证据；之前的 Eta/Mika 研究或未来优化候选不能自动变成 Ditto 已有功能。

## 怎样更新与验收

每个对照项至少记录：**原产品版本与证据 → 预期行为/协议 → PocketRun 实现入口 → 自有或授权场景的结果 → 剩余差距**。

- 架构路线一致，只表示采用同类执行机制。
- 一个章节任务通过，只证明对应设备、制品和场景。
- 完整功能覆盖，需要清单里的已确认目标逐项完成；未知项不能偷偷当作已经没有或已经通过。

第 12—13 章原有计划继续推进，但章节编号不是功能范围上限。补齐清单后可以增加必要章节；最小实现扩展为完整同类能力时，不能放松当前权限、手机批准、数据保护及资源所有权边界。
